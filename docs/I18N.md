# Internationalization

ncasa supports Spanish (`es`) and English (`en`) at runtime through `@ngx-translate`.
Spanish is the fallback language. The selected language is persisted under `ncasa.language`; when no
preference exists, the application uses a supported browser language and otherwise falls back to
Spanish.

## Adding user-facing copy

1. Add a semantic, feature-scoped key to both `public/i18n/es.json` and `public/i18n/en.json`.
2. Use `TranslatePipe` in templates and import it into the standalone component.
3. Store translation keys, not translated labels, in TypeScript configuration arrays.
4. Keep domain values, API codes and user-created content language-neutral. Translate them only at
   the presentation boundary.
5. Store dates as ISO values and use the localized presentation pipes. Never put formatted dates in
   domain or demo data.
6. Translate visible text, placeholders, validation feedback, metadata and accessible names.

Run `npm run check:i18n` to verify catalog parity, followed by the complete test suite and production
build.
